# R0 — Architecture Prototype

## Purpose

Select the production architecture using evidence rather than preference.

## Required common scenario

Every candidate must implement the same synthetic scenario:

1. Start at tile (1, 1).
2. Attempt to walk into a blocked tile.
3. Walk to tile (3, 1).
4. Trigger an interaction event.
5. Continue until the deterministic encounter trigger fires.
6. Save state.
7. Reload state.
8. Continue with identical results.
9. Present the state on an Android device.
10. Accept both touch and physical-controller input.

## Candidates

### A — C core + SDL3/OpenGL

Purpose: establish the lowest-overhead native baseline.

### B — C core + Godot bridge

Purpose: measure whether the existing/ported C gameplay core can remain authoritative while Godot owns presentation and Android integration.

### C — Godot reimplementation

Purpose: establish the productivity and visual-flexibility ceiling, while measuring the cost of rewriting gameplay truth.

## Evaluation dimensions

- Reuse of existing Vanilla+ behavior
- Android build/deployment complexity
- Renderer and UI freedom
- Asset and animation workflow
- Determinism/regression testing
- Debuggability across the native/engine boundary
- Runtime performance and frame consistency
- Save/lifecycle integration
- Long-term maintenance cost
- Ease of adding desktop/Android TV targets

No candidate wins merely by rendering a prettier prototype.

## R0 exit criteria

R0 is complete only when:

- all viable candidates run the common scenario;
- Android hardware execution is demonstrated for the finalists;
- core-state regression tests pass;
- lifecycle/save behavior is tested;
- performance measurements are recorded;
- an ADR records the selected architecture and rejected alternatives.

## Non-goals

R0 does not include:

- production Hoenn art;
- complete Emerald data import;
- full battle system migration;
- final touch UI;
- visual polish;
- content expansion.
